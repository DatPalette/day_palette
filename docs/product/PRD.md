## 1. 背景与目标

### 1.1 问题

用户在**出门、拍照、聚餐、游玩**前，常为**穿什么色系、是否贴合场合**而纠结；需要**低负担**工具，而非衣橱管理或内容社区。

### 1.2 产品目标

- **MVP**：30 秒～1 分钟内确定 **今日 2～3 个主色 + 场合标签**，并在 **App 与桌面服务卡片** 上一致展示；支持 **免费出图分享**。  
- **商业目标（无广告）**：通过 **Pro（Form 皮肤 + 高级配色包）** 变现；免费能力完整、付费边界清晰。

### 1.3 成功指标（首版可轻量化）

| 指标 | 说明 |
|------|------|
| **功能完整** | 免费用户可走通：选场合 → 套组/推荐/微调 → 保存今日 → 出图 → 添加桌面卡片。 |
| **质量** | 免费套组「不丢人」；随机/规则生成不出现明显脏色（见规划第十一章）。 |
| **合规** | 商店与 IAP 描述与实现一致；恢复购买可用。 |

## 2. 范围定义

### 2.1 MVP 内（必须做）

| ID | 需求概要 |
|----|-----------|
| F-01 | **今日状态**：持久化 `primary/secondary/accent` 三色（HEX）、`occasionId`、`shortNote`（上限如 20 字）、`templateId`、`updatedAt` 及规划中的预留字段。 |
| F-02 | **场合/风格**：单选枚举（休闲 / 通勤 / 约会 / 运动风 / 聚会 等，可配置）；与配色 **联动推荐**（本地 JSON 规则）。 |
| F-03 | **选色路径**：一键套组（横滑）、先场合再推荐、沿用昨日、随机（仅安全集或规则生成）、精调（二级入口）；**禁止**裸随机 RGB。`昨日` 定义为 **上一自然日最后留在本地的 draft 配色**，仅保留轻量快照，不建立历史列表。 |
| F-04 | **主界面预览**：主次分区版式（约 55～65% / 25～30% / 10～15%），叠字 **自动对比度**；套组缩略图与主预览 **比例一致**。 |
| F-05 | **出图 + 分享**：本地渲染，当前首版聚焦 **1:1** 输出；**多套基础版式模板对用户完全免费**（当前已落地 Editorial / Columns / Thirds / Mosaic / Stack）；Share Kit 分享。 |
| F-06 | **Form 服务卡片**：至少 **中卡**（建议再加小卡）；展示色条、场合/短签；数据与 App **同源**；点击进入今日页。 |
| F-07 | **设置**：语言切换、微缩预览样式（Capsule / Hero）、减少动效、轻微颗粒、外观跟随系统信息、关于；**恢复购买**；Pro 状态展示。 |
| F-08 | **IAP**：**Pro 一次性解锁** — 解锁 **Form 皮肤包** + **高级配色包**（具体 SKU 以 AppGallery Connect 配置为准）；免费套组 + 免费出图不受影响。 |

### 2.2 MVP 外（明确不做）

- 数字衣橱、单品拍照、OOTD 日记、社区与信息流。  
- 强制云同步用户数据。  
- **3.3 本周常穿**、**3.4 洗护提醒**：功能与入口不上线；数据层允许 `ext` 占位。

### 2.3 预留（实现期落地）

- Intents：「打开今日配色」直达今日页（V1 目标，可与 MVP 并行若工时允许）。  
- Debug：**强制免费 / 强制 Pro** 切换（见 `docs/test-release-checklist.md`）。

## 3. 用户与场景

### 3.1 目标用户

偏 **18～35 岁、注重穿搭与情绪价值**的用户（不限性别）；重视 **桌面一眼可见** 与 **分享图好看**。

补充判断：

- 当用户**已经知道今天要去做什么**时，更需要的是**穿搭决策**。  
- 当用户**没有明确安排，只想随便走走或临时决定做什么**时，更需要的是**情绪灵感**。  
- 产品交互上不新增“先选你属于哪一种状态”的更重前置分流，而继续通过统一场景体系承接这两类需求；必要时可在今日页补一个轻量的“灵感入口”承接“先看看、先找感觉”的状态。

### 3.2 核心场景（用户故事）

1. **作为用户**，我打开 App，希望 **先选今天场合**，然后 **一键得到和谐三色**，少在色盘上纠结。  
2. **作为用户**，我希望 **滑几下套组** 就能换风格，并 **微调某一格** 颜色。  
3. **作为用户**，我希望把今日配色 **存成图片发朋友**，且 **不付费也能用全基础模板出图**。  
4. **作为用户**，我希望 **桌面小部件** 和 App 里是 **同一套颜色与场合**。  
5. **作为付费用户**，我希望 **桌面卡片更漂亮**，并有 **更多精选配色套组**。
6. **作为用户**，当我今天**没有固定安排**时，我希望先看几组**被策展过的安全灵感配色**，再决定是否进入某个具体场景。

## 4. 功能需求详述

### 4.1 今日页（唯一主导航 Tab）

- **核心形态（Editorial Style）**：抛弃传统工具型的干瘪交互，采用「高级时尚杂志」的展示理念（Daily Curated Inspiration）。
- **布局设计**：
  - **顶部导航**：悬浮毛玻璃（Frosted Glass）效果，包含**日期**（点击设置按钮展开侧滑面板）。**不展示**占位城市/定位文案；若未来接入真实定位或天气，再定义顶栏信息结构（见 §9 未来规划）。
  - **Hero 预览区**：沉浸式重叠色卡（带细微噪点质感），采用优雅的衬线体（Serif）大标题展示当前选中套组的名称（如无套组名则兜底显示「今天的故事」情绪）。
  - **选项区（Scroll Content）**：可在 Hero 下方补一个轻量**灵感入口**，用于承接“今天没安排、先看看”的状态；中部为极简文字横滑的**场合选择**（去 Emoji 化）；下部为对应场合的**精选配色盘**。
  - **底部操作**：悬浮毛玻璃底栏，极简黑白「保存」与「分享」按钮。
- **高级交互（Sticky Mini-Hero）**：当用户向下滚动导致大预览区滑出屏幕时，顶部导航栏进入紧凑态。左侧日期淡出并切换为当前套组名，中央浮现可点击的微缩预览；微缩预览样式可在设置中切换为 `Capsule` 或 `Hero cards`。用户在底部切换配色时，紧凑态预览实时变化（所见即所得），点击该预览可丝滑滚回顶部。
- **状态**：修改即生效，沉浸式体验。  
- **灵感入口边界**：灵感入口不是新的正式场景，不与 `workday / weekend / outdoor / dinner` 并列；它只负责先展示 3～5 组被策展过的安全 palette，用户选中后仍落回现有 palette 主链路。
- **昨日规则（轻量版）**：应用仅维护 `today draft` 与 `yesterday snapshot` 两个本地槽位；跨自然日启动或应用回前台时，若当前 draft 属于昨天，则滚动为 `昨日`。隔多日未打开时，不把更早草稿误判为昨日，也不建立按天历史；无有效昨日快照时，“沿用昨日”入口弱化并禁用。  
- **空状态**：首次启动直接展示「工作日/通勤」的推荐套组大图，让用户直接被美感击中，而非面对空白的选择表单。

### 4.2 配色数据

- **免费套组**：内置 `palettes.json` 子集，**15～25 组**为合理首版目标（可迭代）。  
- **高级套组**：Pro 解锁额外 JSON 资源或内置加密标记读取；**逻辑与免费同一套代码**。  
- **场合 → 默认色**：`occasion-palette-rules.json`（或等价结构），仅本地。
- **内容结构演进**：中期建议将配色资产拆为 **基础单色库（Base Color）/ 配色盘（Palette）/ 专题合集（Collection）** 三层，便于复用、重组、专题策展与智能配规则建设。  
- **首批专题方向（探索中）**：优先围绕 **Citywalk 拍照 / 公园出片 / 国风新中式** 三类相对稳定、低翻车风险的场景做策展验证。  
- **更新机制约束**：当前若配色数据完全内置，则内容调整通常需随应用版本发布；后续若引入远端覆盖，必须补齐离线降级、版本兼容与回滚策略。

### 4.3 出图

- 分辨率：至少 **1080 短边** 级；比例可先做 **1:1**。  
- 当前基础模板：**Editorial / Columns / Thirds / Mosaic / Stack**，均免费开放；其中 `Stack` 与主 Hero 构图同源。  
- 出图以点击当下的页面状态生成快照，再进入导出/分享链路，避免与用户继续编辑后的界面状态错位。  
- **无付费墙**拦截基础导出。

### 4.4 Form

- **中卡**优先保证可读性与安全区。  
- **皮肤**：免费默认 1 套；Pro 解锁多 `skinId`，渲染层读 `isPro` + `skinId`。

### 4.5 设置与多语言

- **交互形式**：从主界面右侧平滑滑出的原生侧滑面板（Slide-in Panel），确保沉浸感不断层。
- **国际化（i18n）**：首发支持中英双语无缝切换。
  - **英文配置**：Cormorant Garamond (展示) + DM Sans (UI)
  - **中文配置**：Noto Serif SC (展示) + Noto Sans SC (UI)
  - **文案深度本地化**：如 "Sweet Escape" 对应 "桃汽周末"，追求情绪传达与高级感，而非生硬机翻。
- **Pro 与基础设置**：
  - 微缩预览支持 **Capsule / Hero cards** 两种样式，设置面板内需直接展示可见预览差异。  
  - 展示 **当前是否 Pro**；入口 **购买 Pro**、**恢复购买**。  
  - 商品说明须列出 **含哪些皮肤、含哪些配色包**；是否在文档中约定「是否包含未来 DLC」须与商店文案一致。

### 4.6 智能配（方向约束）

- 智能配前期走**保守规则**路线，目标是 **不出错、稳定、可解释**，而不是开放式生成。  
- 第一阶段建议以“用户给定主色 + 场景”作为输入，从已审核的安全候选池中补全 `secondary / accent`。  
- 推荐结果优先保证“可穿、稳妥、符合场景”，再逐步拉开表达差异。  
- 智能配能力与现有“精调”不是互相替代，而是作为主路径增强；完整自由微调能力仍保留为展开态。

## 5. 非功能需求

| 类别 | 要求 |
|------|------|
| **隐私** | 默认 **无自有云存储**；权限最小化；相册仅在保存/分享时说明用途。 |
| **性能** | 今日页冷开可接受范围内；出图在后台线程，不长时间阻塞 UI。 |
| **无障碍** | 系统「减弱动态效果」；主/辅/点有文字角色标签。 |
| **视觉** | **去色化高级感（Neutral UI）**：背景采用极简米白/浅灰，克制使用界面色彩（去渐变），使**「主/辅/点缀色」成为唯一的视觉焦点**。重叠的物理色卡带有真实的噪点（Noise）质感。 |

## 7. 验收标准（MVP）

- [x] 免费用户：可选场合、套组、微调，**保存后 Form 与 App 一致**（同源 Preferences；卡片按 Form 刷新策略更新）。  
- [x] 免费用户：**任意基础模板**可出图并分享，**无需 Pro**。  
- [ ] 未购 Pro：高级套组与付费皮肤 **不可选或显示锁 + 引导购买**。  
- [ ] 已购 Pro：皮肤与高级套组 **立即可用**；杀进程重进 **权益保持**；**恢复购买**成功。  
- [ ] Debug：**强制免费 / 强制 Pro** 可测全链路（仅 Debug 包）。  
- [ ] 无数字衣橱、无 OOTD、无广告。

## 9. 未来规划（未立项实现）

以下**不作为当前迭代交付**，立项时需单独补：权限说明、隐私政策、失败降级与离线策略。

| 方向 | 说明 |
|------|------|
| **天气与配色** | 接入**系统天气**能力，或基于**用户定位**请求合规天气服务；将气象维度（晴雨、温区、光照体感等）映射为**配色推荐/提示**（规则表或独立策略模块，与现有 `occasion → palette` 可并行或融合）。 |
| **顶栏信息升级** | 在能稳定获取天气时，顶栏可由「仅日期」升级为 **日期 + 天气摘要**（如图标 + 短文案），提升「今天出门」语境；定位城市标签仅在实际有数据源时再展示，避免占位文案。 |
| **权限与合规** | 定位、天气、网络访问须在 PRD 子章节与商店说明中逐项列出；默认最小权限，拒绝授权时功能降级为当前「手动选场合 + 本地套组」体验。 |
| **内容更新机制** | 若后续要降低“每次调 palette 都要发版”的成本，可评估 **本地基础库 + 远端 JSON 覆盖**；但在正式引入前，必须先补缓存、失败回退、版本兼容与审核流程。 |
