# 灵感入口方案

## 1. 文档定位

本文合并以下两份旧文档：

- `inspiration-entry-plan.md`
- `inspiration-entry-ui-draft.md`

目标是把“灵感入口”统一收敛为一份可直接承接产品、设计与实现的文档。

当前要解决的问题不是新增一套独立信息架构，而是在不打散 DayPalette 现有主路径的前提下，为“今天没有固定安排、只想先看看色彩感觉”的用户补一个低负担入口。

---

## 2. 问题与产品判断

当前 DayPalette 的主路径是：

1. 先选场景。
2. 再看对应 palette。
3. 再随机、沿用昨日或精调。

这条路径适合“我知道今天要去做什么”的用户，但对另一类真实状态并不够自然：

- 今天没有固定安排。
- 想先看看有没有一点色彩灵感。
- 不想一上来就回答“我今天属于哪个场景”。

### 2.1 不建议直接新增正式场景

不建议把“随便看看”或“今天没安排”做成与 `workday / weekend / outdoor / dinner` 并列的正式场景。

原因：

1. 现有场景更像“去哪里 / 做什么”。
2. “先找感觉”更像当前决策状态，而不是稳定场景分类。
3. 两者维度不同，硬塞进同一层会让场景体系越来越难解释。

### 2.2 更适合做轻量入口

更合理的处理方式是：

- 把它做成一个“灵感入口”。
- 先承接“我还没想好”的状态。
- 再把用户导回现有选 palette 主链路。

它不是一个新的一级场景分类体系，而是一个进入 palette 浏览的捷径。

## 3. 推荐方案

### 3.1 方案名称

任务和文档层统一称为：

- 灵感入口

面向用户的显示文案再单独挑选，不直接把“灵感入口”作为最终按钮文案。

### 3.2 推荐放置位置

推荐优先采用：

- 在 Hero 下方、场景横滑条上方放一个轻量入口卡。

理由：

1. 语义最清楚。
2. 不和 `随机选 / 沿用昨日 / 精调` 混在一起。
3. 用户更容易理解为“在选场景之前，也可以先找感觉”。

不优先采用的方案：

- 放进 `随机选 / 沿用昨日 / 精调` 那组动作入口。
- 做成首次进入分流或独立页面。

### 3.3 推荐交互流

1. 用户进入首页后，依次看到 Hero、灵感入口、场景横滑条和当前场景列表。
2. 点击入口后，不跳新页面，优先使用首页内联展开区。
3. 展示 3 到 5 组精选灵感 palette，每组只给简短情绪标签，不先强绑正式场景。
4. 用户点击某组 palette 后：
   - Hero 立即切到该 palette。
   - 首页主 palette 列表同步定位到对应项。
   - 若该 palette 已有主场景，可弱提示其更偏向的语境。
5. 选中后自动收起展开区，回到首页正常浏览状态。

要求：

1. 不丢失刚刚选中的 palette。
2. 不把用户强行标记到某个新场景。
3. 不新增额外持久化状态字段，除非后续验证确实有必要。

## 4. UI 结构与状态

### 4.1 页面层级

推荐首页顺序：

1. TopBar
2. Hero
3. 灵感入口
4. 场景横滑条
5. palette 横滑列表
6. 底部操作区

### 4.2 入口默认形态

推荐默认形态为一条横向轻入口卡，而不是纯文字链接。

建议结构：

- 左侧：小型情绪文案
- 中部：一句主标题
- 右侧：轻箭头或“看看”提示

当前推荐口径：

- Eyebrow：今天没安排？
- Title：今日灵感
- Trailing hint：先从这几组开始

更克制的简化版本也可成立：

- 主标题：今日灵感
- 副标题：先从这几组开始

### 4.3 点击后的展开形态

首版推荐使用“首页内联展开区”。

推荐结构：

1. 标题行
2. 一组灵感 palette 卡片
3. 一个收起动作

标题行建议：

- 标题：今天先看这几组
- 辅助说明：每天会换一组新的推荐，不必先决定场景

每张灵感卡片建议包含：

1. 三色色条或缩略构图
2. palette 名称
3. 1 个情绪标签
4. 可选的弱场景提示，例如“偏周末”“偏轻户外”“偏城市漫游”

注意：

1. 弱场景提示不能被用户理解成新场景分类。
2. 不要让灵感卡承担正式导航职责。

### 4.4 至少定义的 4 种状态

1. 默认未展开：只看到入口卡。
2. 已展开：展示 3 到 5 张灵感卡。
3. 已选中某组灵感：Hero 和主列表同步切换，并自动收起。
4. 空结果或兜底：回退为一条轻提示，例如“今天先从当前场景里看看吧”。

首版既然是人工精选池，应尽量避免进入空结果状态。

### 4.5 动效建议

首版只建议做轻量动效：

1. 入口点击后，展开区淡入并轻微下展开。
2. 卡片选中时，目标卡片做一次短暂强调。
3. Hero 切换沿用现有 palette 切换动效。

不建议首版做：

- 全屏 modal 级大动效
- 横滑与纵向展开混合的大范围联动
- 复杂共享元素动画

## 5. 数据来源与实现边界

### 5.1 数据来源建议

首版不建议为灵感入口单独建立一整套新数据模型。

建议来源优先级：

1. 从现有 `safe` 或高质量 curated palette 中精选。
2. 优先选择跨场景也成立、情绪明确、翻车风险低的 palette。
3. 如后续要加强，可再从 `Collection` 中增加“灵感池”标签。

首版更推荐：

- 先用人工精选 palette 池做验证。

如果要进一步自动化，推荐两种路径：

1. 方案 A：基于现有本地候选池做稳定轮换。
2. 方案 B：在数据文件中新增轻量标签，例如 `entryTags: ['inspiration']`。

建议顺序：

- 第一轮先做方案 A。
- 确认长期保留后，再演进到方案 B。

### 5.2 最小组件拆分建议

推荐最小新增组件：

1. `InspirationEntryCard.ets`：默认收起态入口卡。
2. `InspirationPaletteStrip.ets`：展开后的灵感 palette 列表。

可复用能力：

1. 现有 Hero 渲染能力。
2. 现有 palette 选中与滚动定位能力。
3. 现有 palette 卡片视觉语言。
4. 现有 ViewModel 内选中 palette 的写回链路。

### 5.3 ViewModel 最小改动建议

建议最少新增：

1. `isInspirationExpanded`：控制展开与收起。
2. `getInspirationPaletteIds()`：返回当前入口展示的 palette 列表。
3. `applyInspirationPalette(paletteId)`：复用当前 palette 选中逻辑，并触发 Hero / 列表同步。

当前不建议首版新增：

1. 独立 Page
2. 独立导航路由
3. 独立持久化 store
4. 独立灵感场景枚举

## 6. 文案与命名收敛建议

### 6.1 当前推荐文案

中文入口文案当前最推荐：

- 今日灵感

英文入口文案当前最推荐：

- Today's Picks

理由：

1. 更像“今天这份固定推荐”，而不是一次点击触发一次生成。
2. 能弱化“每次点开都应看到不同内容”的预期。
3. 更符合当前产品的克制气质。

### 6.2 Hero 与场景文案边界

建议统一口径：

1. `今天的故事` 仍可保留为 Hero 全局兜底标题。
2. 不建议把“随便走走的一天”之类表达设为固定场景名。
3. 正式场景优先保持清晰、可理解、可映射到实际出门语境。
4. 灵感态表达优先放在入口文案、Hero 副标题和专题描述。

这样可以避免“场景”和“情绪状态”混层。

## 7. 最小实现清单

### 7.1 UI 层

1. 在首页 Hero 下方插入灵感入口卡。
2. 为入口卡增加展开/收起状态。
3. 展开后展示 3 到 5 组灵感 palette 缩略卡。
4. 点击灵感卡后，触发现有 palette 选中逻辑。
5. 选中后自动收起展开区。

### 7.2 状态层

1. 在 ViewModel 中增加入口展开状态。
2. 提供灵感 palette ID 列表。
3. 提供应用灵感 palette 的统一方法。

### 7.3 数据层

1. 选定首版灵感 palette 池。
2. 明确每组 palette 对应的名称和轻量情绪标签。
3. 不新增正式场景 key。

### 7.4 文案层

1. 确认中文入口文案。
2. 确认英文入口文案。
3. 确认展开区标题与辅助说明。
4. 确认每张灵感卡的标签口径。

### 7.5 验收层

1. 用户可以不先选场景，直接通过入口看到灵感 palette。
2. 灵感入口不会把用户误导成进入新场景体系。
3. 选中灵感 palette 后，Hero 与主列表保持同步。
4. 与 `随机选` 的语义差异清晰可感知。
5. 首页不会因为入口展开而显著打乱原有节奏。

---

## 8. 当前建议

如果下一轮真的进入设计或开发，最稳妥的路径是：

1. 先按首页内联展开区画 UI。
2. 先用人工精选 palette 池做首版验证。
3. 先验证“灵感入口”是否真的比“加一个新场景”更顺。
4. 验证有效后，再考虑把它沉淀为更稳定的数据标签或专题入口。

最终建议只有一句话：

不要把“先找感觉”的用户状态硬塞进正式场景体系，而是给它一个轻量入口，再把用户自然导回现有主链路。
