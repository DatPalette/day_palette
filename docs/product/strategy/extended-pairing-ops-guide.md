# 扩展搭配运营指导文档

## 1. 文档目的

这份文档用于说明 DayPalette 当前“扩展搭配”能力里，哪些内容可以由运营维护，应该改哪里，改完后怎么自检。

当前这套能力不是开放式生成，而是：

- 基于已审核 palette 资产做延展推荐。
- 通过规则过滤高风险组合。
- 用模板化文案给出简短解释。

因此，运营侧当前主要维护的是“场景口径”和“解释模板”，不是直接改算法本体。

---

## 2. 当前真实维护入口

当前第一优先维护文件：

- `entry/src/main/resources/rawfile/smartmatch/strategy.v1.json`

这份文件负责两类内容：

1. 解释模板。
2. 场景策略配置。

当前代码会在启动阶段读取这份 JSON，并在扩展搭配结果里优先使用其中的配置。

---

## 3. 可以修改的字段

### 3.1 `templates`

用于控制解释文案的模板。

- `sceneMatch`
  - 作用：解释“为什么适合当前场景”。
- `layerBalance`
  - 作用：解释主色、辅色、点缀色的层次关系。
- `safeResult`
  - 作用：解释“为什么这套更稳妥”。
- `styleHint`
  - 作用：解释整体风格偏向。

每个模板都有：

- `zh`
- `en`

当前支持的占位符：

- `sceneMatch`：`{occasion}`、`{mood}`
- `styleHint`：`{styleHint}`

约束：

- 不要删除占位符。
- 不要把一句文案写得过长，建议控制在 1 句内。
- 不要使用过度绝对化表达，例如“永远不会出错”“一定高级”。

### 3.2 `fallbackScene`

用于兜底。当某个场景没有单独配置时，会使用这组默认值。

- `tabooFamilies`
  - 作用：该场景默认禁配的颜色家族。
- `mood`
  - 作用：该场景默认情绪描述。

### 3.3 `scenes`

用于维护具体场景策略。当前已接入的 app 场景包括：

- `workday`
- `weekend`
- `outdoor`
- `dinner`

每个场景可维护：

- `tabooFamilies`
  - 例：`orange`、`red`、`purple`、`green`
- `mood.zh`
- `mood.en`

约束：

- 当前只应编辑已存在的场景 key。
- 如果要新增场景 key，必须先确认客户端场景入口也支持该 key。
- `tabooFamilies` 只写颜色家族，不写自然语言句子。

---

## 4. 不建议直接修改的内容

以下内容当前不建议由运营直接修改：

- 代码里的硬规则与排序逻辑。
- palette / collection 的结构字段名。
- `strategy.v1.json` 的顶层结构。
- 还没有进入产品主路径的实验场景 key。

如果需要改这些内容，应先在产品任务或策略文档中确认，再进入代码调整。

---

## 5. 推荐维护流程

### 5.1 日常小改

适用于：

- 想调整解释口吻。
- 想收紧或放松某个场景的禁配色家族。
- 想统一中英文场景气质描述。

建议流程：

1. 先在 `strategy.v1.json` 修改对应字段。
2. 检查中英文是否语义一致。
3. 检查模板占位符是否保留完整。
4. 在 app 中验证 `workday / weekend / outdoor / dinner` 至少各看 1 次结果。
5. 若文案或禁配边界影响明显，再进入主分支提交。

### 5.2 场景扩充

适用于：

- 要把 `Citywalk 拍照 / 公园出片 / 国风新中式` 补进当前策略层。

建议流程：

1. 先确认产品侧最终场景命名。
2. 再确认客户端是否已有对应场景 key 或映射关系。
3. 为每个场景补：
   - `mood`
   - `tabooFamilies`
   - 对应解释模板是否需要额外收敛
4. 最后再验证这些场景下结果是否拉开差异，而不是只改文案不改策略口径。

---

## 6. 审核清单

每次改完策略文件，至少检查这 6 项：

1. 中英文文案是否表达同一件事，而不是一个偏感性、一个偏工具说明。
2. 模板占位符是否仍然完整可替换。
3. `tabooFamilies` 是否写成客户端可识别的颜色家族值。
4. 文案是否过长，导致结果卡片阅读负担变重。
5. 语气是否仍然符合 DayPalette 的克制、稳妥、可解释定位。
6. 修改后是否导致四个现有场景看起来没有差异，或差异过度夸张。

---

## 7. 当前已知边界

- 当前“扩展搭配”仍然是有限候选，不是开放式随机生成。
- 当前场景模板已覆盖 app 里的四个既有场景，但还没有把 `Citywalk 拍照 / 公园出片 / 国风新中式` 正式补入配置。
- 当前运营可维护的是模板和场景口径，不是整套候选池生产流程。
- 若后续要把运营维护扩展到 palette 级资产，需要再补表格字段、审核清单和发布流程文档。

---

## 8. 建议的下一步

1. 先把 `Citywalk 拍照 / 公园出片 / 国风新中式` 收敛成正式场景 key 或映射表。
2. 为 `strategy.v1.json` 补一版更完整的审核示例。
3. 再决定是否需要引入表格导出或脚本校验，降低手改 JSON 的出错率。
