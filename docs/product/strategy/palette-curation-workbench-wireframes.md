# 配色策展工作台页面线框与交互草案

## 1. 文档定位

本文用于承接 [palette-curation-workbench-mvp-plan.md](./palette-curation-workbench-mvp-plan.md) 中定义的 MVP 方向，进一步细化页面结构、信息层级与关键交互。

本文不追求高保真视觉稿，而是回答以下问题：

1. 工作台首版应有哪些核心页面。  
2. 每个页面的信息层级应如何组织。  
3. 高频操作应放在哪里。  
4. 筛选、预览、比较、标记之间的交互链路应如何衔接。

---

## 2. 一句话结论

这套工作台的页面设计，应围绕“**高密度预览 + 快速筛选 + 快速标记 + 快速比较**”组织，而不是围绕传统表单后台组织。

也就是说：

- 首屏应先看到候选，而不是先看到编辑表单。  
- 高频操作应尽量在列表或卡片层完成。  
- 详情页只承担补充判断和少量编辑，不应成为主要入口。  

---

## 3. 全局布局建议

## 3.1 整体布局

建议采用典型工作台布局：

```text
+----------------------------------------------------------------------------------+
| Top Bar: 场景切换 | 搜索 | 结果数 | 视图切换 | 导入 | 校验 | 导出 |
+----------------------------------------------------------------------------------+
| Left Filter Rail   | Main Workspace                                             |
| 场景               |                                                            |
| 状态               |                                                            |
| 风格               |                                                            |
| 情绪               |                                                            |
| 安全等级           |                                                            |
| 明度/饱和度        |                                                            |
| 评分               |                                                            |
| 是否入选           |                                                            |
|                    |                                                            |
+----------------------------------------------------------------------------------+
| Bottom Utility Bar: 已选数量 | 批量标记 | 对比 | 恢复 | 备注 | 发布前检查 |
+----------------------------------------------------------------------------------+
```

## 3.2 设计原则

1. 左侧永远保留筛选面板。  
2. 顶部永远保留场景切换、搜索和视图切换。  
3. 底部或浮动工具栏承担批量操作。  
4. 详情不应强制跳页，可优先用右侧抽屉或浮层展开。  

这能最大化维持“看大量候选时的连续性”。

---

## 4. 页面一：配色盘总览页

## 4.1 页面目标

用于完成：

1. 快速进入某个场景。  
2. 浏览候选总量。  
3. 进行初步筛选。  
4. 快速把候选送入预览或对比流程。

## 4.2 线框建议

```text
+----------------------------------------------------------------------------------+
| 场景: [通勤 v] [Citywalk] [约会] [公园] [更多...]   搜索框         [网格][表格]   |
+----------------------------------------------------------------------------------+
| 筛选                                                                             |
| 状态: 全部 / candidate / shortlisted / approved / rejected                       |
| 风格: urban / soft / natural / minimal / ...                                     |
| 情绪: relaxed / clear / bright / quiet / ...                                     |
| 安全等级: safe / expressive / experimental                                       |
| 评分: 0-5                                                                        |
+----------------------------------------------------------------------------------+
| 结果 124 项    已入选 16    待定 48    淘汰 60                                   |
+----------------------------------------------------------------------------------+
| [卡片] [卡片] [卡片] [卡片] [卡片]                                               |
| [卡片] [卡片] [卡片] [卡片] [卡片]                                               |
| [卡片] [卡片] [卡片] [卡片] [卡片]                                               |
+----------------------------------------------------------------------------------+
| 批量操作: [加入对比] [标记待定] [标记淘汰] [标记入选] [添加备注]                 |
+----------------------------------------------------------------------------------+
```

## 4.3 卡片层必须支持的快捷操作

1. 单击进入详情。  
2. 双击快速放大预览。  
3. 勾选加入批量操作。  
4. 快捷标记 `shortlisted`。  
5. 快捷标记 `rejected`。  
6. 快捷加入对比。

## 4.4 交互要点

1. 筛选条件变化后不跳页，只局部刷新列表。  
2. 卡片可支持键盘导航。  
3. 鼠标悬停时显示关键元信息。  
4. 总览页应允许直接完成第一轮筛选，不必频繁进入详情。

---

## 5. 页面二：批量预览页

## 5.1 页面目标

这是整个工作台的核心页面，目标是：

1. 让你在短时间内扫过大量候选。  
2. 直接看到配色盘进入产品后的大致效果。  
3. 快速做“保留 / 待定 / 淘汰”的审美判断。

## 5.2 线框建议

```text
+----------------------------------------------------------------------------------+
| 视图: 今日页主卡 | 列表卡片 | 详情氛围 | 对比入口     密度: 紧凑 / 标准 / 放大   |
+----------------------------------------------------------------------------------+
| 筛选摘要: 场景=Citywalk, 状态=candidate, 风格=urban, 结果=38                     |
+----------------------------------------------------------------------------------+
| [今日页缩略卡] [今日页缩略卡] [今日页缩略卡] [今日页缩略卡]                      |
| 名称 / 场景 / 评分 / 状态 / 快捷操作                                              |
|                                                                                  |
| [今日页缩略卡] [今日页缩略卡] [今日页缩略卡] [今日页缩略卡]                      |
| 名称 / 场景 / 评分 / 状态 / 快捷操作                                              |
+----------------------------------------------------------------------------------+
| 快捷键: A=入选  S=待定  D=淘汰  C=加入对比  E=详情                               |
+----------------------------------------------------------------------------------+
```

## 5.3 预览卡片信息层级

每张卡片建议分成四层：

1. 第一层：模拟真实页面的视觉缩略图。  
2. 第二层：配色盘名称、场景标签、状态。  
3. 第三层：评分、风险提示、是否入选。  
4. 第四层：快捷操作按钮。

## 5.4 交互要点

1. 支持卡片密度切换。  
2. 支持批量键盘操作。  
3. 支持按评分或最近修改排序。  
4. 支持将当前筛选结果整体送入对比池。  

---

## 6. 页面三：对比页

## 6.1 页面目标

用于解决“相似候选之间谁更稳、谁更值得保留”的问题。

## 6.2 线框建议

```text
+----------------------------------------------------------------------------------+
| 对比池 4 项          [自动推荐相似项] [按名称排序] [按评分排序]                   |
+----------------------------------------------------------------------------------+
| [候选A]            | [候选B]            | [候选C]            | [候选D]            |
| 今日页缩略图       | 今日页缩略图       | 今日页缩略图       | 今日页缩略图       |
| 三色角色条         | 三色角色条         | 三色角色条         | 三色角色条         |
| 文本可读性         | 文本可读性         | 文本可读性         | 文本可读性         |
| 风险提示           | 风险提示           | 风险提示           | 风险提示           |
| [保留] [淘汰其余]  | [保留] [淘汰其余]  | [保留] [淘汰其余]  | [保留] [淘汰其余]  |
+----------------------------------------------------------------------------------+
| 底部对比说明: 可记录“为何保留 A 而淘汰 B”                                       |
+----------------------------------------------------------------------------------+
```

## 6.3 对比维度建议

1. 页面整体气质。  
2. 层次感是否足够。  
3. 标题与标签可读性。  
4. 与同组候选的差异度。  
5. 是否更符合当前场景语义。

## 6.4 交互要点

1. 支持一键保留一个并批量淘汰其它。  
2. 支持把对比结论直接写入 `reviewNotes`。  
3. 支持重新加入待定池。  
4. 支持自动推荐相似配色盘进入对比池。

## 7. 页面四：入选与淘汰管理页

## 7.1 页面目标

这个页面不是为了再次预览，而是为了沉淀和追溯决策。

## 7.2 线框建议

```text
+----------------------------------------------------------------------------------+
| Tabs: 已入选 | 待定 | 已淘汰 | 已归档                                             |
+----------------------------------------------------------------------------------+
| 左侧列表                               | 右侧详情                                  |
| 候选名称                               | 名称                                      |
| 场景                                   | 当前状态                                  |
| 评分                                   | 评分                                      |
| 最后修改时间                           | 淘汰原因 / 入选理由                       |
|                                        | 备注                                      |
|                                        | 相关对比记录                              |
|                                        | [恢复] [移动状态] [加入发布集]            |
+----------------------------------------------------------------------------------+
```

## 7.3 交互要点

1. 支持按场景查看最终候选集。  
2. 支持一键恢复误淘汰项。  
3. 支持从已入选集生成发布候选集。  
4. 支持查看历史备注与最近操作。

---

## 8. 页面五：单个配色盘详情页

## 8.1 页面目标

详情页承担两个职责：

1. 做更精细的人工判断。  
2. 做少量必要编辑。

## 8.2 线框建议

```text
+----------------------------------------------------------------------------------+
| 标题: 薄雾街角                    状态: shortlisted      [上一项] [下一项]        |
+----------------------------------------------------------------------------------+
| 左侧大预览                           | 右侧属性与备注                           |
| 今日页主卡                           | 基础信息                                 |
| 列表卡片                             | 场景 / 风格 / 情绪                       |
| 深底模式                             | 安全等级 / 评分                          |
| 浅底模式                             | 审核状态                                 |
|                                      | 备注                                     |
|                                      | 淘汰原因                                 |
|                                      | [保存] [加入对比] [标记淘汰]            |
+----------------------------------------------------------------------------------+
| 相似候选推荐                                                                    |
+----------------------------------------------------------------------------------+
```

## 8.3 交互要点

1. 详情页应支持左右切换上一项和下一项。  
2. 修改评分和状态后应即时保存或显式提示。  
3. 相似候选区域应一键送入对比。  
4. 详情页应支持原始数据查看入口，但不应成为主编辑方式。

## 9. 页面六：发布前检查页

## 9.1 页面目标

用于把“策展工作流”衔接到“正式发布工作流”。

## 9.2 线框建议

```text
+----------------------------------------------------------------------------------+
| 发布前检查                                                                        |
+----------------------------------------------------------------------------------+
| 校验摘要: 错误 3 | 警告 7 | 场景 5 | 已入选 42 | 待发布 18                       |
+----------------------------------------------------------------------------------+
| 左侧问题列表                           | 右侧问题详情                            |
| 缺失字段                               | 具体字段与修复建议                      |
| 引用错误                               | 涉及配色盘                              |
| 命名冲突                               | 是否阻塞发布                            |
| 对比度风险                             | [跳转到详情] [标记忽略]                 |
+----------------------------------------------------------------------------------+
| 底部: [构建预览 Bundle] [导出] [提交到资产仓库]                                  |
+----------------------------------------------------------------------------------+
```

## 9.3 交互要点

1. 区分阻塞错误与非阻塞警告。  
2. 支持从错误直接跳转回对应配色盘。  
3. 支持只导出当前场景。  
4. 支持先构建预览 bundle，再决定是否正式发布。

---

## 10. 关键交互流

## 10.1 初筛流

1. 进入总览页。  
2. 选择场景。  
3. 进入批量预览页。  
4. 快速标记 `shortlisted / rejected / candidate`。  
5. 将相似项送入对比页。  
6. 把结果沉淀到状态管理页。

## 10.2 精筛流

1. 从待定池进入对比页。  
2. 选出较优候选。  
3. 打开详情补充评分与备注。  
4. 更新为 `approved` 或 `rejected`。  
5. 进入入选集。

## 10.3 发布流

1. 从入选集生成发布候选。  
2. 打开发布前检查页。  
3. 处理错误和警告。  
4. 构建 bundle。  
5. 提交到资产仓库或导出本地。

## 11. 首版实现优先级

## 11.1 P0

1. 总览页。  
2. 批量预览页。  
3. 对比页。  
4. 状态标记。  
5. 基础备注。

## 11.2 P1

1. 详情页。  
2. 入选与淘汰管理页。  
3. 基础发布前检查页。

## 11.3 P2

1. 原始数据查看入口。  
2. 批量编辑。  
3. 更复杂的相似项推荐。  
4. 更完整的发布链路。

---

## 12. 最终建议

页面和交互层面最重要的判断只有一个：

**不要把它做成表单后台，要把它做成视觉策展工作台。**

因此首版线框设计应围绕以下原则：

1. 预览优先。  
2. 列表内完成高频操作。  
3. 对比能力前置。  
4. 状态沉淀可追溯。  
5. 发布流程后置。

只要这几点不偏，后续无论继续走本地 Web 还是封装为桌面端，产品方向都不会偏离。
