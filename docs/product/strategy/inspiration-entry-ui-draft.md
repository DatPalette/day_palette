# 灵感入口 UI 结构草案与最小实现清单

## 1. 文档目的

这份文档用于把“灵感入口”从产品概念继续下钻到设计与实现可直接承接的层级。

目标是回答两类问题：

1. UI 上应该长什么样。
2. 首版如果要做，最小要改哪些点。

本文默认以前一份方案文档 [inspiration-entry-plan.md](./inspiration-entry-plan.md) 为前提，不再重复解释产品背景。

---

## 2. 首版范围

首版只处理以下范围：

1. 首页新增一个灵感入口。
2. 点击后展示 3 到 5 组精选灵感 palette。
3. 用户点击任一 palette 后，直接落回现有主链路。
4. 不新增独立页面。
5. 不新增正式场景。
6. 不新增远端数据依赖。

---

## 3. 推荐 UI 结构

## 3.1 页面层级

推荐首页顺序如下：

1. TopBar
2. Hero
3. 灵感入口
4. 场景横滑条
5. palette 横滑列表
6. 底部操作区

其中灵感入口位于 Hero 与场景横滑条之间。

原因：

1. 语义上最接近“在选场景之前，先找感觉”。
2. 不会与 `随机选 / 沿用昨日 / 精调` 混淆。
3. 视觉上可被理解为 Hero 的延伸动作，而不是 palette 卡片操作。

---

## 3.2 入口默认形态

推荐默认形态为一条横向轻入口卡，而不是纯文字链接。

建议结构：

- 左侧：小型情绪文案
- 中部：一句主标题
- 右侧：轻箭头或“看看”提示

建议文案结构：

- Eyebrow：今天没安排？
- Title：今日灵感
- Trailing hint：先从这几组开始

如果需要更克制，也可压缩为：

- 主标题：今日灵感
- 副标题：先从这几组开始

---

## 3.3 点击后的展开形态

首版推荐使用“首页内联展开区”，不推荐首版就上新页面。

### 推荐结构

入口点击后，在原位置下方展开一个内容区：

1. 标题行
2. 一组灵感 palette 卡片
3. 一个收起动作

标题行建议：

- 标题：今天先看这几组
- 辅助说明：每天会换一组新的推荐，不必先决定场景

### 卡片建议

每张灵感卡片建议包含：

1. 三色色条或缩略构图
2. palette 名称
3. 1 个情绪标签
4. 可选的弱场景提示

弱场景提示示例：

- 偏周末
- 偏轻户外
- 偏城市漫游

注意：

- 不要把弱场景提示做成主标题。
- 不要让用户误以为这就是新场景分类。

---

## 3.4 展开区状态

首版至少要定义 4 种状态。

### 状态 A：默认未展开

用户看到入口卡，但内容区关闭。

### 状态 B：已展开

展示 3 到 5 张灵感卡。

### 状态 C：已选中某组灵感

用户点击某张卡后：

1. Hero 切到该 palette。
2. 主 palette 列表同步定位。
3. 展开区可自动收起，或保留短暂选中反馈后收起。

首版建议：

- 选中后自动收起。

这样更利落，也避免首页同时展开过多层。

### 状态 D：空结果或兜底

如果灵感池暂时不可用：

- 不展示空白面板。
- 回退为一条轻提示。

示例：

- 今天先从当前场景里看看吧

但首版既然是人工精选池，理论上应尽量避免进入该状态。

---

## 3.5 动效建议

首版只建议做轻量动效：

1. 入口点击后，展开区淡入并轻微下展开。
2. 卡片选中时，目标卡片做一次短暂强调。
3. Hero 切换沿用现有 palette 切换动效，不单独新做复杂动画。

不建议首版做：

- 全屏 modal 级大动效
- 横滑与纵向展开混合的大范围联动
- 复杂共享元素动画

---

## 4. 组件拆分建议

若下一轮进入实现，推荐最小拆分如下。

### 4.1 可新增组件

1. `InspirationEntryCard.ets`
作用：默认收起态入口卡。

2. `InspirationPaletteStrip.ets`
作用：展开后的灵感 palette 列表。

### 4.2 可继续复用的现有能力

1. 现有 Hero 渲染能力
2. 现有 palette 选中与滚动定位能力
3. 现有 palette 卡片视觉语言
4. 现有 ViewModel 内选中 palette 的写回链路

### 4.3 不建议首版新增的东西

1. 独立 `Page`
2. 独立导航路由
3. 独立持久化 store
4. 独立灵感场景枚举

---

## 5. ViewModel 最小改动建议

首版最小实现建议只增加轻量状态，不要重构主数据流。

建议最少新增：

1. `isInspirationExpanded`
作用：控制入口展开与收起。

2. `getInspirationPaletteIds()`
作用：返回当前灵感入口展示的 palette 列表。

3. `applyInspirationPalette(paletteId)`
作用：复用当前 palette 选中逻辑，并触发 Hero / 列表同步。

### 可选但非首版必需

1. `lastInspirationSeed`
2. `dismissedInspirationHint`
3. 灵感入口曝光埋点

这些都不是首版必要条件。

---

## 6. 数据来源最小方案

首版建议直接采用本地人工精选列表。

推荐两种轻量方案：

### 方案 A：基于现有本地 palette 池做稳定轮换

优点：

- 不需要手动维护固定 palette ID 名单。
- 后续新增 palette 可自然进入轮换。
- 可按“当天稳定、隔天变化”的方式提供更轻的更新感。

缺点：

- 首版结果的策展感略弱于完全人工精选。

### 方案 B：在现有本地数据资源中增加轻量标签

例如：

- `isInspirationPick: true`
- 或 `entryTags: ['inspiration']`

优点：

- 更利于后续维护。

缺点：

- 会涉及数据文件补字段和 mapper 调整。

当前更推荐：

- 第一轮验证先用方案 A，采用“本地候选池 + 当日稳定轮换”。
- 如果确认长期保留，再迁到方案 B，把入口候选池下沉为数据侧可维护标签。

## 7. 最小实现清单

以下清单按“下一轮可直接开工”的粒度给出。

### 7.1 UI 层

1. 在首页 Hero 下方插入灵感入口卡。
2. 为入口卡增加展开/收起状态。
3. 展开后展示 3 到 5 组灵感 palette 缩略卡。
4. 点击灵感卡后，触发现有 palette 选中逻辑。
5. 选中后自动收起展开区。

### 7.2 状态层

1. 在 ViewModel 中增加入口展开状态。
2. 提供灵感 palette ID 列表。
3. 提供应用灵感 palette 的统一方法。

### 7.3 数据层

1. 选定首版灵感 palette 池。
2. 明确每组 palette 对应的名称和轻量情绪标签。
3. 不新增正式场景 key。

### 7.4 文案层

1. 确认中文入口文案。
2. 确认英文入口文案。
3. 确认展开区标题与辅助说明。
4. 确认每张灵感卡的标签口径。

### 7.5 验收层

1. 用户可以不先选场景，直接通过入口看到灵感 palette。
2. 灵感入口不会把用户误导成进入新场景体系。
3. 选中灵感 palette 后，Hero 与主列表保持同步。
4. 与 `随机选` 的语义差异清晰可感知。
5. 首页不会因为入口展开而显著打乱原有节奏。

---

## 8. 设计师 / 开发接手前需确认的两项决策

在真正进入实现前，建议先确认这两个点。

### 决策 1：展开方式

二选一：

1. 首页内联展开区
2. 轻量弹层

当前推荐：

- 首页内联展开区

### 决策 2：首版灵感池来源

二选一：

1. 完全人工精选 palette IDs
2. 数据文件打轻量标签

当前推荐：

- 先完全人工精选

---

## 9. 暂定结论

下一轮若进入设计或开发，最稳妥的路径是：

1. 先按首页内联展开区画 UI。
2. 先用人工精选 palette 池做首版验证。
3. 先验证“灵感入口”是否真的比“加一个新场景”更顺。
4. 验证有效后，再考虑把它沉淀为更稳定的数据标签或专题入口。
